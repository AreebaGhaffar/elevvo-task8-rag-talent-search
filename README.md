# RAG-Powered Talent Search Engine — Elevvo Task 8

Ask a resume database in plain English — *"Find me a Junior Data Analyst who
knows SQL and Tableau"* — and get ranked candidates, an LLM-written fit
summary, a verified skill-match verdict, and a bias check. Built as a
Retrieval-Augmented Generation (RAG) pipeline over 220 labelled resumes.

## Dataset

**Resume Entities for NER** (Kaggle, owner DataTurks) —
https://www.kaggle.com/datasets/dataturks/resume-entities-for-ner

- 220 manually labelled resumes from indeed.com, 10 entity categories
  (Name, College Name, Degree, Graduation Year, Years of Experience,
  Companies worked at, Designation, Skills, Location, Email Address).
- Kaggle listing: 1,220,776 bytes total, updated 2018-07-12, licence Unknown.
- **Source substitution (recorded):** the Kaggle API host is unreachable
  from this VM through the egress proxy, so the identical official files
  were fetched from the DataTurks GitHub export instead —
  https://github.com/DataTurks-Engg/Entity-Recognition-In-Resumes-SpaCy
  (`traindata.json` 1,106,139 bytes = 200 resumes,
  `testdata.json` 111,557 bytes = 20 resumes), verified byte-exact
  (total 1,217,696 bytes; the ~3 KB difference is Kaggle packaging).
  `download_data.py` tries the Kaggle API first, then the GitHub fallback
  with size verification.

Exploration (`results/exploration_summary.md`): resume text mean 472 words
(median 400, min 29, max 1250). Annotated in the pool: name 218,
designation 202, skills 183, degree 192, companies 190 of 220 resumes.
Mean 1.6 Skills spans per resume; mean years of experience 4.8 where
stated; graduation years 1980–2018 (21 distinct values). Data quirks:
files are JSONL, not a JSON array; 2 annotations carry label `UNKNOWN`;
2 "Years of Experience" values are just a year ("2004") and are ignored.

## Setup

CPU-only, ~6 GB RAM. Python 3.10+.

```bash
python -m venv .venv && source .venv/bin/activate
pip install torch==2.5.1 --extra-index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
python download_data.py     # resumes -> data/
python download_models.py   # embedding + LLM models -> models/  (curl, size-verified)
python build_index.py       # embed + index into chroma_db/  (add --faiss for a FAISS copy)
```

Models (gitignored, downloaded with `curl` because the HF Hub downloader
stalls/returns truncated files on this VM):
- `sentence-transformers/all-MiniLM-L6-v2` — embeddings (90,868,376 bytes)
- `Qwen/Qwen2.5-0.5B-Instruct` — local generation LLM (988,097,824 bytes)

`transformers==4.57.1` is pinned: transformers v5 removed the pipelines API.

## How to run

```bash
# Semantic search (top-5 candidates with similarity scores)
python cli.py search "Find me a Junior Data Analyst who knows SQL and Tableau"

# Search + LLM fit summaries + verified skill-match verdicts
python cli.py explain "Find me a Junior Data Analyst who knows SQL and Tableau" --k 3

# Search + bias check (top-k vs the whole pool)
python cli.py bias "Java developer with Spring and Oracle experience" --k 10

# Per-candidate Q&A ("Does this candidate have leadership experience?")
python cli.py ask train-002 "Does this candidate have leadership experience?"

# Retrieval evaluation (10 queries, P@k / R@k)
python -m src.evaluate

# LangChain retrieval chain (same index, LangChain RetrievalQA-style)
python -m src.langchain_rag "Junior Data Analyst who knows SQL"

# Streamlit UI — query box, top candidates, LLM fit summary,
# bias check panel, per-candidate Q&A
streamlit run app.py
```

## How it works

1. **Parse & chunk** (`src/resume_store.py`): each resume is split into
   labelled sections (Skills, Work Experience, Education, …); sections are
   chunked at ~900 characters with 150 overlap → **1,562 chunks from 220
   resumes**.
2. **Embed & index**: `all-MiniLM-L6-v2` (384-dim) into a persistent
   ChromaDB collection (`chroma_db/`); a FAISS index
   (`outputs/faiss_index/`, verified: 1,562 vectors, dim 384) is built as
   a fallback with `build_index.py --faiss`.
3. **Retrieve** (`src/search.py`): the query is embedded and the top-k
   chunks are returned with cosine-similarity scores, de-duplicated to
   one entry per resume with its best chunk as evidence.
4. **LLM-based evaluation** (`src/llm.py`): the top 3 resumes go to the
   local LLM for a one-sentence profile summary, **plus a deterministic
   fit verdict computed from the dataset's own NER annotations** —
   required skills are extracted from the query by matching it against
   the pool's skill vocabulary; each candidate is checked by
   word-boundary matching against its annotated Skills/Designation:
   **STRONG** (all required found) / **PARTIAL** (some) / **WEAK** (none).
   The verdict is never generated by the LLM — see *Why the verdict is
   computed, not generated* below.
5. **Bias Check** (`src/bias.py`): the retrieved top-k is compared with
   the whole 220-resume pool on explicitly labelled attributes only —
   graduation-year cohort, college, location, years-of-experience band.
   A group is flagged when its share differs by more than 25 percentage
   points, or when one group is ≥ 80% of the top-k while < 50% of the
   pool. **No protected attribute is ever inferred from names or photos**
   (the dataset has neither).
6. **Per-candidate Q&A** (`src/llm.py:answer_question`): the candidate's
   resume is passed as context to the local LLM; an extractive fallback
   (best keyword-overlap sentence) is always shown as evidence, and the
   model answers "Not stated in this resume" when the answer is absent.

### Why the verdict is computed, not generated

`google/flan-t5-base` was tested first and **rejected**: it echoed the
query back as the "summary" and hallucinated fit — e.g. it claimed
Meenalochani Kondya, a .NET/ASP engineer, "is a junior data analyst who
knows SQL and Tableau". `Qwen2.5-0.5B-Instruct` writes fluent, grounded
profile summaries, but it also has a strong affirmation bias: even when
explicitly told a skill is missing, it still claims the candidate
"excels in" it (verified with several prompt variants, including a
structured found/missing prompt and yes/no QA). A 0.5 B local model
cannot be trusted with the free-form fit narrative, so the design is:
**LLM writes the profile summary; the fit verdict is computed from the
annotations.** With a stronger API model the narrative can be trusted —
see the API hook below.

### API hook (OpenAI / Gemini)

`src/llm.py` accepts `backend="openai"` or `backend="gemini"` with
`OPENAI_API_KEY` / `GEMINI_API_KEY` set; it calls the provider's REST
endpoint with plain stdlib `urllib` (no extra dependency). No key is on
file in this project, so the local model is the default and the API path
is an optional, documented swap-in for a reviewer.

### Retrieval evaluation — 10 hand-built queries (pool = 220 resumes)

Gold sets are built from the NER annotations: a resume is gold if it
has ≥ 1 of the query's skills in its Skills annotation **and** a matching
role keyword in its Designation. Full table:
`results/retrieval_evaluation.{txt,csv,json}`.

| Query | gold | P@5 | P@10 | R@10 |
|---|---:|---:|---:|---:|
| Junior Data Analyst, SQL, Tableau | 44 | 0.60 | 0.40 | 0.09 |
| Java developer, Spring, Oracle | 65 | 0.60 | 0.70 | 0.11 |
| Software tester, Selenium, manual testing | 25 | 0.80 | 0.80 | 0.32 |
| Web developer, HTML, CSS, JavaScript | 21 | 0.20 | 0.30 | 0.14 |
| Network engineer, CCNA, routing | 18 | 0.60 | 0.50 | 0.28 |
| Customer support executive, communication | 8 | 0.20 | 0.20 | 0.25 |
| UI designer, Photoshop, user experience | 34 | 0.40 | 0.30 | 0.09 |
| Accountant, Tally, Excel | 1 | 0.20 | 0.10 | 1.00 |
| Project manager, Agile, leadership | 5 | 0.00 | 0.00 | 0.00 |
| SAP consultant, ABAP, HANA | 15 | 0.80 | 0.70 | 0.47 |

**Mean (n = 10): P@5 0.44, P@10 0.40, R@10 0.27.** Recall is low partly
because the loose gold definition makes some gold sets very large
(up to 65 resumes), so R@10 is inherently capped. The Project Manager
query scores 0 — semantic search misses it entirely, because "Agile"
and "leadership" are rarely stated in this pool's annotations.

### Bias Check — worked example (full output: `results/bias_check_examples.txt`)

Query *"Junior Data Analyst who knows SQL and Tableau"*, top-10 vs pool:

- **Graduation cohort — FLAGGED:** 2006–2012 is 50% of the top-10 but
  20% of the pool (+30 pp); "unknown" graduation year is 20% of the
  top-10 but 53% of the pool (−33 pp). Resumes with a stated graduation
  year (older, more complete resumes) rank higher — the flag is a prompt
  for the recruiter to review, not proof of discrimination. Note that
  graduation year is an age proxy, which is exactly why it is surfaced.
- Location: Bengaluru 40% of top-10 vs 22% of pool (+18 pp, not flagged).
- College: top-5 colleges combined 0% of top-10 vs 6% of pool (not
  flagged; colleges are nearly unique — ~190 distinct for 194 labelled
  resumes — so per-college shares are meaningless and the check uses the
  combined top-5 share).
- Experience band: 85% of the pool has no stated years of experience,
  so the band comparison is weak by construction.

The Java query flags the same cohort pattern (2006–2012: 50% vs 20%
pool). No flag was raised for college, location, or experience band in
either query.

## Limitations

- **2018 dataset, Indian resumes from Indeed.** Skills and roles reflect
  that era/pool (Tableau is in only 5 resumes' text; "Spring" appears in no Skills
  annotation). Results do not generalise to today's market.
- **Local 0.5 B LLM.** Qwen2.5-0.5B-Instruct writes grounded summaries
  but has a strong affirmation bias and can ramble; that is why the fit
  verdict is computed from annotations, not generated. For a production
  narrative, use the OpenAI/Gemini hook with a stronger model.
- **Verified match is conservative:** it checks annotated Skills and
  Designation only, so a candidate who mentions a skill only in free
  text is marked "missing" (e.g. PRASHANTH BADALA and Oracle).
- **Annotations are noisy:** 37 of 220 resumes have no Skills
  annotation; only 33 state years of experience; 2 annotations are
  labelled `UNKNOWN`; location spellings vary (Bengaluru/Bangalore).
- **Retrieval is modest** (mean P@5 0.44 on 10 queries) — small noisy
  pool, loose gold definition, and MiniLM embeddings. A larger model or
  hybrid keyword+semantic retrieval would help.
- **Bias Check is a screen, not a verdict:** it compares shares on
  labelled attributes only, on a top-10 sample (one resume = 10 pp), and
  cannot detect bias in attributes the data does not label.
